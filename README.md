# Daisy Days 🌼

**บันทึกรอบเดือนแบบออฟไลน์ — ข้อมูลอยู่ในเครื่องคุณเท่านั้น**
Offline-first period & symptom tracker. Your data never leaves your device.

[**▶ เปิดใช้งาน / Open the app**](https://duanganucha.github.io/daisydays-web/)

`HTML` · `CSS` · `JavaScript` — ไม่มี framework ไม่มี build step ไม่มีเซิร์ฟเวอร์

</div>

---

## ทำอะไรได้

- 📅 **ปฏิทิน** — แตะวันที่เพื่อบันทึกวันมีประจำเดือน ดูวันที่คาดการณ์และช่วงเจริญพันธุ์ในหน้าเดียว
- 📝 **บันทึกรายวัน** — ปริมาณ อารมณ์ อาการ 12 แบบ และโน้ตส่วนตัว
- 📊 **สถิติ** — รอบเฉลี่ย ความแปรปรวน ช่วงสั้นสุด–ยาวสุด กราฟความยาวรอบย้อนหลัง อาการที่พบบ่อย
- 🔮 **คาดการณ์** — คำนวณจาก 6 รอบล่าสุดของคุณเอง พร้อมบอกระดับความแม่น (ไม่โกหกว่าแม่นตอนข้อมูลยังน้อย)
- 🌐 **ไทย/อังกฤษ** สลับได้ทันที
- 🌙 **ธีมสว่าง/มืด** หรือตามระบบ
- 📴 **ออฟไลน์เต็มรูปแบบ** — ติดตั้งเป็น PWA แล้วใช้ได้โดยไม่ต้องต่อเน็ต
- 💾 **ส่งออก/นำเข้า JSON** — ย้ายเครื่องหรือสำรองข้อมูลได้เอง

## ความเป็นส่วนตัว

ข้อมูลรอบเดือนเป็นข้อมูลสุขภาพที่อ่อนไหวที่สุดอย่างหนึ่ง แอปนี้ออกแบบให้**ไม่มีทางรู้ข้อมูลของคุณได้เลย**:

| | |
|---|---|
| เซิร์ฟเวอร์ | ❌ ไม่มี — เป็นไฟล์ static ที่ GitHub Pages เสิร์ฟ |
| บัญชีผู้ใช้ | ❌ ไม่มี |
| analytics / tracker | ❌ ไม่มี |
| cookie | ❌ ไม่มี |
| ปลายทางที่ข้อมูลถูกส่งไป | ❌ ไม่มี |
| ที่เก็บข้อมูล | ✅ `localStorage` ของเบราว์เซอร์คุณเท่านั้น |

คำขอข้ามเครือข่ายเดียวที่แอปยิงคือฟอนต์ IBM Plex Sans Thai จาก Google Fonts — ถ้าไม่ต้องการเลยแม้แต่อันนั้น ลบสองบรรทัด `<link>` ใน `index.html` ออกได้ แอปใช้ฟอนต์ระบบแทนทันที

> ⚠️ **ข้อแลกเปลี่ยน:** ไม่มีคลาวด์ = ไม่มีการสำรองอัตโนมัติ ถ้าล้างข้อมูลเบราว์เซอร์ ข้อมูลหาย → **ส่งออกไฟล์สำรองเป็นระยะ** (ตั้งค่า → ส่งออกไฟล์สำรอง)

## รันในเครื่อง

ไม่ต้อง `npm install` ไม่ต้อง build เพราะเป็น HTML/CSS/JS ล้วน

```bash
git clone https://github.com/duanganucha/daisydays-web.git
cd daisydays-web
python3 -m http.server 8000
# เปิด http://localhost:8000
```

> ต้องเสิร์ฟผ่าน HTTP จริง ไม่ใช่เปิดไฟล์แบบ `file://` เพราะแอปใช้ ES modules ซึ่งติดข้อจำกัด CORS

## โครงสร้างโค้ด

```
daisydays-web/
├── index.html          โครงหน้าเปล่า + meta tags (UI ถูกวาดด้วย JS)
├── manifest.json       PWA manifest
├── sw.js               service worker — cache-first ให้ใช้ออฟไลน์ได้
├── css/
│   └── app.css         สไตล์ทั้งหมด + ธีมสว่าง/มืดผ่าน CSS custom properties
├── js/
│   ├── store.js        ชั้นข้อมูล: localStorage, ช่วงประจำเดือน, บันทึกรายวัน, ส่งออก/นำเข้า
│   ├── cycle.js        ตรรกะล้วน: สถิติรอบ คาดการณ์ ช่วงเจริญพันธุ์ ตารางปฏิทิน
│   ├── i18n.js         ข้อความไทย/อังกฤษ + จัดรูปแบบวันที่
│   └── app.js          UI ทั้งหมด: ปฏิทิน แผ่นบันทึก สถิติ ตั้งค่า
└── icons/              ไอคอนแอป (SVG + PNG 192/512/maskable)
```

**หลักการแบ่งไฟล์:** `cycle.js` เป็นฟังก์ชันบริสุทธิ์ที่รับ state แล้วคืนค่า ไม่แตะ DOM และไม่แตะ storage เลย — เทสต์ง่ายและย้ายไปใช้ที่อื่นได้

### รูปแบบข้อมูล

```js
{
  version: 1,
  settings: { lang: 'th', theme: 'auto', cycleLength: 28, periodLength: 5 },
  periods: [ { start: '2026-09-01', end: '2026-09-05' } ],
  logs: {
    '2026-09-03': { flow: 'medium', symptoms: ['cramps'], mood: 'tired', note: '' }
  }
}
```

ไฟล์ที่ส่งออกคือ JSON ก้อนนี้ตรง ๆ — อ่านออก แก้ด้วยมือได้ ไม่มีรูปแบบปิด

## การคาดการณ์ทำงานอย่างไร

1. เก็บ **วันเริ่ม**ประจำเดือนทุกครั้ง
2. ความยาวรอบ = ระยะห่างระหว่างวันเริ่มที่ติดกัน (กรองค่าที่เป็นไปไม่ได้: นอกช่วง 15–90 วัน)
3. เฉลี่ย **6 รอบล่าสุด** → ความยาวรอบที่ใช้คาดการณ์
4. วันเริ่มถัดไป = วันเริ่มล่าสุด + ความยาวเฉลี่ย (ทบไปเรื่อย ๆ)
5. ไข่ตกโดยประมาณ = 14 วันก่อนรอบถัดไป ช่วงเจริญพันธุ์ = 5 วันก่อน ถึง 1 วันหลัง
6. ความแม่น: `none` → `low` (1-2 รอบ) → `medium` (3-4) → `high` (5+) และบอกว่า "สม่ำเสมอ" เมื่อส่วนเบี่ยงเบนมาตรฐาน ≤ 4 วัน

เป็นสถิติพื้นฐานตรงไปตรงมา ไม่มี AI ไม่มีกล่องดำ อ่านโค้ดใน [`js/cycle.js`](js/cycle.js) ได้ทั้งหมด
